# Правила схем

Запрос: $ARGUMENTS

## Шаг 1. Определи тип схемы

| Тип | Что это | Признак | Файл правил |
|-----|---------|---------|-------------|
| 1.1 | Карта воронки CRM | стадии сделки / лида / смарт-процесса колонками, внутри роботы и условия | [funnel-map.md](funnel-map.md) |
| 1.1a | Схема на доработку | карта 1.1, где видно, что инженеру добавить / изменить / удалить | [funnel-map.md](funnel-map.md) §1.1a |
| 1.1b | Связи между воронками | две воронки на листе + стрелки, что передаётся | [funnel-map.md](funnel-map.md) §1.1b |
| 1.3 | Карта роботов стадий | как 1.1, но по реальным роботам портала | [funnel-map.md](funnel-map.md) §1.3 |
| 1.2a | Линейный БП | один шаблон БП, вертикальная цепочка | [bp.md](bp.md) |
| 1.2b | БП со статусами | шаблон со статусами (как в дизайнере Битрикс) | [bp.md](bp.md) §1.2b |
| 1.7 | БП согласования документа | вне стадий CRM: договор, счёт, спецификация | [approval.md](approval.md) |

BPMN от заказчика — это **вход**, не целевой формат: переводи в 1.1 (стадии + блоки).

Тип неясен из запроса — спроси, не угадывай. Ошибка типа = неправильная палитра и раскладка на всей схеме.

## Шаг 2. Прочитай только нужные файлы

1. Файл правил своего типа (таблица выше).
2. [arrows.md](arrows.md) — стрелки, общие для всех типов.
3. [styles.md](styles.md) — готовые стили draw.io. Цвета бери **оттуда**, не подбирай на глаз.

## Шаг 3. Чек-лист перед сдачей схемы

1. Палитры типов **не смешаны**: карта воронки (1.1) ≠ БП (1.2) ≠ согласование (1.7).
2. Стрелки по [arrows.md](arrows.md): не режут блоки, не сливаются, подписи веток на вертикали.
3. Ширина колонок / холста подогнана под содержимое — блоки не пересекаются, нет пустых «дыр».
4. Тексты — названиями, как видит пользователь Битрикс: стадии, поля, списки, сотрудники по-русски, а не `UF_CRM_*`, `DT…`, `БП #ID`.
5. Схема на доработку — разметка добавить / изменить / удалить, легенда и «Открытые вопросы» на листе (§1.1a).
6. Ручную `.drawio` не перезаписывать генерацией без копии.

## Red Flags — остановись, если думаешь так

- «Цвет примерно такой, возьму похожий» → нет, только из [styles.md](styles.md).
- «Заодно упрощу / объединю одинаковые ветки, так красивее» → на схеме доработки это запрещено: инженер переделает работающее.
- «Эту пометку заказчика я понял так-то» → своё толкование идёт в «Открытые вопросы», не в схему как факт.
- «Удалённый блок просто уберу» → удаляемое рисуется перечёркнутым пунктиром, не исчезает молча.
- «Стрелку из низа ромба быстрее» → из боковой вершины.
- «Легенда очевидна, не нужна» → на схеме доработки легенда обязательна.
