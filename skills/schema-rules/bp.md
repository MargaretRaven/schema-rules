# Схема бизнес-процесса (один шаблон БП)

Не путать с картой воронки (1.1) и с согласованием (1.7) — другая палитра и раскладка.

| Подтип | Когда | Раскладка |
|--------|-------|-----------|
| **1.2a** Линейный | обычный последовательный БП | вертикальный стек шагов в узкой колонке (~560 px) + легенда цветов слева |
| **1.2b** Со статусами | шаблон со статусами (state machine) | **2 колонки шахматом** внутри контейнера-обёртки |

## Цвета (БП)

| Цвет | Смысл |
|------|-------|
| Зелёный овал / статус «Старт» | старт БП |
| Зелёный статус «Финиш» | финиш |
| Красный овал | конец / выход с ошибкой (1.2a) |
| Белый блок | действие системы |
| Зелёный блок | задание человеку |
| Жёлтый блок | смена статуса БП / смена стадии |
| Фиолетовый блок | цикл (While), запуск БП |
| Белый ромб | условие / развилка |
| Красный статус | критическая ошибка |
| Серый блок с подписью «отключено» | активити выключено в шаблоне |

Стили — в [styles.md](styles.md).

## Общие правила

- Задания человеку — «Запрос дополнительной информации» / «… с отклонением», не автозадача. Формат текста — как в [funnel-map.md](funnel-map.md) («Тексты блоков»).
- Уведомление — блок «Уведомление» с `Получатели:` / `Сообщение:`, не «Триггер».
- Отключённое активити — серый фон, подпись «отключено». Выключен контейнер / условие — серым всё содержимое.
- Параллельный блок раскрывается до дочерних действий, не рисуется пустым.
- Высота задания — по фактическому числу строк текста, без большого запаса снизу.
- Названия вместо кодов: шаблоны БП, стадии, поля CRM по-русски.
- В панели «Логика процесса» — только смысл БП; правила стрелок туда **не копировать**.

## Правила 1.2b — БП со статусами

1. **Всегда** есть статусы «Старт» и «Финиш» — как swimlane, не отдельные овалы вне статусов.
2. Статусы в **2 колонки шахматом** (как интерфейс дизайнера БП Битрикс):
   - по порядку чередуются левая / правая колонка;
   - каждая колонка уплотняется по вертикали независимо — короткий статус не растягивается до высоты соседа;
   - ширина обеих колонок — под самую широкую N-way развилку.
3. Все статусы внутри **контейнера-обёртки** с названием БП.
4. Блоки «Вход» / «Выход статуса» **не рисуем**.
5. Переходы между статусами — стрелки **от статуса к статусу**. Блок «→ статус …» остаётся внутри статуса как жёлтое действие, а межстатусная стрелка идёт от swimlane к swimlane:
   - между левой и правой колонками — от обращённых друг к другу граней через короткую рельсу в зазоре;
   - внутри одной колонки и для обратных переходов — от боковой грани по отдельной внешней вертикальной рельсе;
   - общую шину над контейнером **не использовать**.
6. Стрелки из ромба — из боковых вершин, горизонталь с подписью, затем вниз.
7. Стрелки слияния выходят из **низа** блоков; горизонтальная шина не режет соседние колонки.
8. Счётчики ошибок (если в процессе повторы) — **отдельные на каждый тип ошибки**, лимит ≤ 3 на тип.
